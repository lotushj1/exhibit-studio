# Exhibit Studio

給展場設計與布展人員的瀏覽器端 3D 模擬工具。建參數化展櫃、每面貼主視覺、擺假人與道具，快速確認尺寸與比例。

## 開源與快速開始

**Live demo：https://exhibit-studio.vercel.app**

需求：Node.js 20 以上（含 npm）。

從 GitHub 複製並啟動開發伺服器：

    git clone https://github.com/lotushj1/exhibit-studio.git
    cd exhibit-studio
    npm ci
    npm run dev

Exhibit Studio 採 local-first 設計：場景資料存在瀏覽器 `localStorage`，貼圖存在瀏覽器 IndexedDB；目前沒有後端上傳流程。要在不同裝置或與同事分享，請使用「專案檔」匯出／匯入 JSON（貼圖會內嵌其中）。

歡迎參閱 [貢獻指南](./CONTRIBUTING.md) 提交修改；本專案採 [MIT License](./LICENSE) 授權。

## 本機執行

    npm install
    npm run dev

開發伺服器在 http://localhost:5180

    npm test          # 單元測試
    npx tsc --noEmit  # 型別檢查
    npm run build     # 型別檢查加打包

## 部署驗收

**正式環境：https://exhibit-studio.vercel.app**

部署命令：

    vercel deploy --target preview --yes
    vercel deploy --prod --yes

正式環境自動驗收：

    npm run verify:deployment -- https://exhibit-studio.vercel.app

Preview 部署受 Vercel SSO protection 保護，匿名瀏覽器無法直接通過；本次以官方 `vercel curl` bypass 驗證首頁、`<title>` 與 JS／CSS 皆回傳 200。正式環境則通過完整 browser gate。

腳本會先以 HTTP follow redirect 讀回 200 與 `<title>`，再以隔離的 `agent-browser` session 驗證頁面載入、單一 Canvas、WebGL2／WebGL context、未落入 WebGLGate、沒有 Vite error overlay、page errors 為零與 console 沒有 error 訊息。驗收結束會關閉隔離 session；腳本不把 URL 內容或任何 token 寫入輸出。

## 物件庫

四種櫃型（分類「展櫃」）：

| 種類 | 說明 |
|---|---|
| 方箱展台 | 寬高深可調，選擇性踢腳（高度、內縮） |
| 玻璃罩高櫃 | 底櫃加五片玻璃薄板（前後左右頂），可選層板 |
| 開放層架 | 側板、頂底蓋板、可調層板數量，選擇性背板 |
| 主視覺背板 | 單片箱體，做展場主視覺牆用 |

假人（分類「人偶」）：一種物件，體型分男性／女性／兒童三種預設，切換體型會連動身高預設值，身高與胖瘦另外可調。

五種道具（分類「道具」）：椅子、板凳、箱子、小櫃子、桌面立牌。

每種物件的可調參數與各面材質，實際定義以 `src/objects/` 底下對應檔案的 `schema`／`surfaces` 為準。

## 操作

| 動作 | 方式 |
|---|---|
| 加入物件 | 左欄「物件庫」分頁點選，物件出現在場景中心（或預設位置） |
| 選取 | 點物件本體，或點左欄「場景清單」分頁 |
| 移動 | 在物件上拖曳，只在地面平面移動 |
| 貼齊移動 | 按住 Shift 拖曳，貼齊 10 公分 |
| 旋轉 | Q 與 E 每次 15 度，或右欄輸入角度 |
| 複製 | Cmd+D（或 Ctrl+D） |
| 刪除 | Delete 或 Backspace |
| 復原與重做 | Cmd+Z 與 Cmd+Shift+Z（或 Ctrl 對應鍵） |
| 取消選取 | Esc |
| 改名 | 在場景清單裡單擊選取物件列；雙擊名稱、或聚焦後按 Enter／F2 進入編輯，失焦或按 Enter 提交 |

以上快捷鍵在輸入框、下拉選單、滑桿、開關等控制項聚焦時不會觸發（避免拖滑桿或選完下拉選單後，焦點還留在控制項上時誤觸刪除或旋轉）。

## 尺寸規則

介面所有長度都是公分。物件尺寸由參數決定並重新產生幾何，不使用縮放，因此貼圖不會變形，尺寸標註也永遠等於實際幾何。

各物件的尺寸邊界以 schema 定義為準，例如開放層架的總高最小 60 公分、層板厚度與側板厚度上限都是 4 公分；實際數字請以 `src/objects/` 對應檔案為準，本文件不重複列出每一項數值以免與程式碼不同步。

## 貼圖

每個面各自獨立上傳。填滿模式會裁切、完整顯示會留白、平鋪會重複，三種都依該面的實際長寬比計算，不會把圖拉變形。

每個面的「顯示方式」有兩種：

- **受光顯示**（預設）：貼圖跟一般材質一樣受光照與展櫃底色影響，看起來比較像實際印在櫃體上、被現場燈光打過的樣子。
- **原色顯示**：完全不受光照與底色影響，也不過 tone mapping，螢幕上的顏色就是圖檔本身的顏色。要確認主視覺的實際色彩時用它。

貼圖存在瀏覽器的 IndexedDB，場景結構存在 localStorage，關掉分頁再回來內容還在。要換電腦或給同事，用「專案檔」匯出 JSON，貼圖會內嵌在裡面。

## 尺寸標註與截圖

開啟「尺寸標註」開關會在選取的物件旁顯示寬高深的公分數字。互動畫面上的數字是疊在 3D 畫面上方的 HTML（不是 3D 幾何本身），但「截圖」功能會在擷取畫面時額外把這些數字重新合成到輸出的 PNG 上，所以下載下來的截圖一樣看得到標註數字，不會少掉。截圖支援目前解析度（1x）與兩倍解析度（2x）兩種。截圖永遠反映按下當下的投影模式與外觀（深色／淺色），標註底色與文字顏色會跟著切換，不會出現螢幕上看到淺色、截圖卻是深色底的不一致。

## 投影模式

頂列「透視／正交」切換相機的投影方式：

- **透視**：預設模式，有近大遠小的透視效果，符合人眼直覺，適合一般檢視。
- **正交**：沒有透視收斂，物件的實際比例不受距離影響，適合看平面配置圖（俯視最明顯）或需要精確比例參考的場景。

切換時相機會用跟切換相機預設一樣的 0.6 秒平滑過渡（正交模式用 `zoom` 取代透視的視野角，效果對等）。五種相機預設在正交模式下都可以正常切換與截圖；其中「人眼視角」在正交模式下沒有意義（正交沒有透視收斂，1.6 公尺的相機高度與 50mm 等效焦距不會呈現任何視覺效果），因此在正交模式下會退化成跟「側視」一樣的角度，而不是整個消失或停用——這樣使用者不會發現五個預設少一格可選。為了不讓這件事悄悄發生，正交模式下「人眼視角」那一格的標籤會改成「人眼視角（＝側視）」，切回透視時恢復原本的「人眼視角」。

投影模式是檢視偏好，不進復原歷史（Cmd+Z 不會把它還原），也不會被存進場景存檔或專案檔。

切換投影時畫面會短暫重繪（黑一下再恢復）：這不是動畫效果，是因為切換的實作方式必須整個銷毀重建 WebGL context（見下方「已知限制」）。重建期間介面會顯示「切換投影中…」，待新 Canvas 完成兩個 `requestAnimationFrame` 且提示至少可見約 300ms 後自動消失。這一輪沒有取得可信毫秒數，也沒有可信證據能說明場景或貼圖數量與成本的關聯；不可用背景分頁節流或不完整樣本推估。

## 外觀（深色／淺色）

頂列「深色／淺色」切換整體介面與 3D 畫面的外觀；淺色是新訪客與沒有有效偏好時的預設，深色仍可隨時切換。淺色模式的預設櫃體使用中等暖灰，和背景保有圖形分離；3D 視埠背景色、地面格線、選取外框、尺寸標註線與文字都會跟著切換到看得清楚的對比色（例如淺色模式下選取外框與標註線改成深色，不然白色會融進淺色背景）。Radix Themes 的 `accentColor="gray"`、`grayColor="slate"`、`radius="small"` 三項設定固定不變，只有 `appearance` 隨這個開關調整。

外觀偏好存在瀏覽器 localStorage（跟場景存檔用不同的 key），重新整理頁面會記得上次選的外觀；但它不會被存進專案檔——匯出專案檔給同事或換電腦開啟，不會連你這台電腦的外觀偏好一起帶過去，也不進復原歷史。

## 專案檔與存檔

- 場景結構（物件、參數、位置）自動存在瀏覽器 localStorage，貼圖存在 IndexedDB，重新整理頁面會自動還原。
- 「專案檔」選單可以匯出成單一 JSON 檔，貼圖以 base64 內嵌在檔案裡；匯入專案檔會還原場景與貼圖，即使當下瀏覽器裡什麼都沒有也能完整還原。
- 物件定義改版（新增/移除參數或面）後，舊存檔會自動用目前的預設值補回缺少的參數與面，不會直接打不開；每個數值也會夾在目前 schema 的合法範圍內，不會出現面板顯示與實際渲染不一致的情況。
- 存檔**格式版本**（`version` 欄位）不同則是另一回事：版本不符會直接視為無法讀取，整份存檔或專案檔被捨棄，不會嘗試部分還原。目前只有一個版本，這種情況實務上不會發生，但要注意這跟上一點「補回缺少欄位」是不同的兩套機制。

## 新增一種物件

在 `src/objects/` 下新增一個檔案，匯出一份 `ObjectDef`：

- `schema`：宣告可調參數（`ParamDef[]`）。每個參數可以定義 `sideEffect`，在這個參數改變時連動調整同物件的其他參數（例如假人切換體型連動身高預設值）；`sideEffect` 只套用一層，不會連鎖觸發其他參數自己的 `sideEffect`。
- `surfaces`：宣告可上材質的面（`SurfaceDef[]`）。
- `Render`：R3F 元件，實際畫出幾何。

再到 `src/objects/registry.ts` 註冊。屬性面板、物件庫、拖曳、存檔會自動支援，不需要改介面程式碼。

## 已知範圍

不做多人協作、自訂燈光編輯、模組自由堆疊組裝、VR／AR，以及擬真渲染（HDRI、光線追蹤、後製特效）。這個工具的定位是快速抓比例，不是出提案圖。

## 已知限制

最終審查比對設計文件與實作後發現的落差，記在這裡而不是假裝不存在：

- **大場景下 2x 截圖會比較慢**：兩倍解析度截圖是把畫面放大重新渲染一次再合成標註文字，物件數量多時這一步會明顯變慢。截圖開始前會先顯示「截圖處理中…」並停用按鈕，但目前仍沒有非同步分批處理或細部進度百分比。
- **不支援 WebGL 的瀏覽器會顯示說明頁**：`WebGLGate` 偵測到瀏覽器/裝置無法建立 WebGL context 時，會整頁換成說明文字，不會嘗試降級成其他渲染方式。
- **貼圖移除後，資產仍留在瀏覽器儲存中，只在下次開啟時清理**：介面上「移除貼圖」只是把該面的材質設定改回純色，底層的貼圖資產（連同 IndexedDB 裡的原始檔）不會立刻刪除，而是留到下次重新整理頁面、場景與貼圖都載入完成後才會掃描一次孤兒資產並清掉。這是刻意的：編輯過程中的復原（Cmd+Z）可能需要用到剛移除的貼圖，只在開機時掃一次可以避免復原失敗，代價是同一個 session 裡貼圖不會即時被回收。
- **切換投影模式時畫面會短暫黑屏重繪**：`Viewport.tsx` 用 `key={projection}` 讓正交／透視切換時整個 `<Canvas>` 卸載重掛（原因見程式碼註解），這會真的銷毀舊的 WebGL context、建立新的，逼所有材質的 shader 重新編譯、所有貼圖重新上傳到 GPU。這是這個實作方式本身的成本，不是單純的動畫效果或開發模式限定的假象。切換期間會顯示「切換投影中…」，待新 Canvas 完成兩個 `requestAnimationFrame` 且提示至少可見約 300ms 後自動消失；本輪沒有可信毫秒數或場景／貼圖成本關聯數據。若未來要量測，應在真人前景 Chrome 重新通過 production、visibility、focus、rAF 與 WebGL draw gates；這一輪沒有進一步改動架構。
